# 침해사고 분석 보고서 (Incident Response Report)
## Meterpreter 감염 및 프로세스 인젝션 사건

**사건번호:** IR-2026-1018
**분류:** 단일 호스트 악성코드 감염 — 메모리 포렌식 분석 (시뮬레이션 랩)
**작성:** DFIR 분석관 (@GAWEON)
**문서 상태:** 최종 초안

> **본 보고서의 성격.** 격리된 실습 랩에서 재현한 모의 침해 시나리오에 대한 분석이다. 감염 상태의 **메모리 이미지를 정식 수집(WinPMEM)하여 무결성(SHA-256)을 확보한 뒤, 검증 사본에서** Volatility 3·Wireshark로 분석하였다. 본 사건은 후속 사건(IR-2026-1019, R2 다중호스트 확산)의 **초기 단계**에 해당한다.

---

## 1. 요약 (Executive Summary)

피해 PC 사용자가 웹에서 내려받은 악성 실행파일을 직접 실행하면서 감염이 시작되었다. 이 악성코드는 외부 공격자 서버와 원격제어(C2) 연결을 맺었고, 탐지를 피하기 위해 정상 프로그램(explorer.exe)에 자신의 코드를 몰래 심었으며, 재부팅 후에도 살아남도록 사용자 영역의 자동실행 항목을 등록하였다. 다만 공격자는 **관리자 권한 획득에는 실패**하여 일반 사용자 수준에 머물렀고, 이 때문에 더 강력한 시스템 수준 지속성 설치는 저지되었다. 자격증명 탈취나 데이터 유출의 직접 증거는 확인되지 않았다. 감염 전 과정이 **메모리·네트워크·레지스트리 세 경로에서 일관되게 교차 확인**되었다. 현재 피해는 해당 PC 1대로 국한되나, C2 세션이 활성 상태였던 점에서 추가 원격 행위 가능성은 배제할 수 없다.

## 4. 상세 분석 (공격 생애주기 순)

### 4-1. 유입 (Initial Access)
- **관측 사실:** 피해 PC가 `hxxp://10.0.0[.]10:8000/invoice.exe`에서 파일을 HTTP로 다운로드. 응답 헤더 `Server: SimpleHTTP/0.6 Python`, `Content-Type: application/x-msdos-program`, 본문에 PE 시그니처(`MZ`, "This program cannot be run in DOS mode"), 크기 7,680 bytes.
- **근거:** Wireshark HTTP 스트림.
- **해석:** 정식 배포 인프라가 아닌 **급조된 Python 간이 웹서버**에서 Windows 실행파일이 배포된 것으로 평가된다.

### 4-2. 실행 (Execution)

- **관측 사실:** `invoice.exe`(PID 2676, 7120)의 **부모 프로세스가 `msedge.exe`(PID 5928)**. 실행시각 12:14:53 UTC.
- **근거:** Volatility `windows.pslist` (프로세스 계보·생성시각).
- **해석:** 브라우저로 내려받은 실행파일을 **사용자가 직접 실행**한 전형적 패턴으로 평가된다.
<img width="1238" height="184" alt="plist" src="https://github.com/user-attachments/assets/888e2423-2966-45e9-88be-06c5466769bc" />


### 4-3. C2 통신 (Command & Control)
- **관측 사실:** `invoice.exe`(2676, 7120)가 **10.0.0[.]10:4444와 ESTABLISHED** 상태. pcap상 해당 세션 2개가 각 약 1 MB, 597 KB 트래픽 교환, 공격자→피해자 방향으로 약 1 MB 전송.
- **근거:** Volatility `windows.netscan`, Wireshark Conversations.
- **해석:** 4444는 Metasploit 기본 포트이며, 공격자가 피해자에게 보낸 약 1 MB는 **meterpreter 본체(staged payload)**로 평가된다. (netscan의 ESTABLISHED는 pcap의 양방향 트래픽으로 교차검증 → **활성 세션**으로 확정. 참고: netscan의 CLOSED 상태였다면 활성 통신으로 단정 불가.)
<img width="1200" height="79" alt="malacts_network_connection" src="https://github.com/user-attachments/assets/a83e60a1-f405-4ed9-a3c2-91f30944b534" />

### 4-4. 코드 인젝션 / 방어 회피 (Defense Evasion)
- **관측 사실:** `malfind`에서 **explorer.exe(PID 3664)**와 **invoice.exe(2676)** 내부에 `PAGE_EXECUTE_READWRITE`(RWX) 권한의 `VadS`(파일 미연결) 영역 존재. explorer 
영역 시작부는 쉘코드(`fc…`), invoice 영역에는 실행파일(`MZ`).
- **근거:** Volatility `windows.malfind` (메모리 영역 권한 + 내용).
- **해석:** 정상 로딩이 아닌 **메모리 직접 주입**으로, meterpreter `migrate` 기법에 의한 프로세스 인젝션의 특징이다. 공격자가 정상 프로세스 explorer로 위장한 것으로 평가된다.
- **경합가설:** RWX 영역은 **정상 JIT(브라우저·.NET 등)에서도 발생**할 수 있다(malfind 오탐 가능). → **기각 근거:** ① explorer.exe는 JIT 호스트가 아니며, ② 영역 내용이 JIT 바이트코드가 아니라 **쉘코드(fc)와 주입된 PE(MZ)**, ③ 동시에 C2 연결·migrate 정황이 존재. 세 근거로 "정상 JIT" 가설을 기각하고 "인젝션"으로 판정.
<img width="1411" height="375" alt="migrate" src="https://github.com/user-attachments/assets/acf34792-dcbd-41c7-9b16-d96ab64c7cd9" />

### 4-5. 지속성 (Persistence)
- **관측 사실:** NTUSER.DAT(HKCU)의 `Software\Microsoft\Windows\CurrentVersion\Run`에 값 `Updater` → `C:\Users\Public\svchost.exe` 등록(키 LastWrite 12:24:00 UTC).
- **근거:** Volatility `windows.registry.printkey`.
- **해석:** 정상 `svchost.exe`는 `System32`에 위치하므로, `C:\Users\Public`의 동명 파일은 **위장(마스커레이딩)**으로 평가된다. 로그온 시 자동실행되는 **사용자 수준 지속성**.
- **경합가설:** 사용자 본인이 등록한 정상 자동실행? → **기각:** 비표준 경로(Public)의 svchost 위장, 감염 시간대 등록, 등록 맥락이 cmd.exe 지속성 작업과 일치. 정상 사용자 행위로 보기 어려움.
- **부정 결과(확인됨):** **HKLM Run 키 등록 및 예약작업 생성은 미발견** → 시스템 수준 지속성은 성립하지 않음. (이는 7·8장의 권한 추론 근거.)
<img width="1422" height="167" alt="runkey" src="https://github.com/user-attachments/assets/2059d882-482e-4f5d-9cd0-9ef67c4bfe78" />


### 4-6. 점검했으나 발견되지 않은 항목 (Negative Findings)

- **자격증명 탈취:** 메모리상 LSASS 접근/덤프 정황 점검 → **직접 증거 미발견.** (단, 메모리 범위 내 한계 존재)
- **횡적 이동(Lateral Movement):** netscan상 C2(10.0.0[.]10) 외 **내부(10.0.0.x) 연결 미발견.**
- **데이터 유출:** pcap상 **대용량 아웃바운드(유출) 트래픽 미발견** (관측된 대용량은 공격자→피해자 인바운드 payload).
- **시스템 수준 지속성:** HKLM Run·예약작업 **미발견**(공격자 시도 실패 추정).

### 4-7. 안티포렌식 점검
- **로그 삭제(Event 1102):** 본 분석은 메모리 중심으로, 보안 이벤트로그 삭제 여부는 **수집 범위 밖 — 미확인(Unconfirmed).**
- **타임스톰프:** **미발견** (관측된 아티팩트 내 시각 조작 흔적 없음).
- **파일 삭제/와이핑:** **미발견.**

## 7. 피해 범위 및 근본 원인 (요약)

- **피해 범위:** **피해 호스트(10.0.0.20) 단일 시스템.** 횡적 이동·자격증명 탈취·데이터 유출의 직접 증거는 미발견(4-6). 단, C2 세션이 활성 상태였으므로 추가 원격 행위 가능성은 배제 불가(Open Question).
- **근본 원인(1줄):** 사용자가 웹에서 내려받은 악성 실행파일을 직접 실행한 것이 최초 감염 경로이며, 실행 시점에 이를 차단할 보안통제가 부재(실험상 Defender 비활성)했다. (상세는 8장)
- **공격자 권한 수준 추론:** **HKLM Run·예약작업 지속성이 실패**한 점에서, 공격자는 **일반 사용자 권한만 확보**(관리자 미획득)한 것으로 평가된다. → 이는 후속 R2에서 공격자가 **권한상승을 시도**하게 되는 배경이 된다.

## 8. 보안 통제 격차 분석

> 통제 상태: ① 통제 부재 / ② 존재하나 우회됨 / ③ 탐지했으나 대응 없음

| 공격 단계 | 미비/실패 통제 | 결과 | 근거 |
|---|---|---|---|
| 실행 | 실행파일 실행 차단(백신/EDR) 부재 ① (실험상 Defender 비활성) | 악성코드 실행 | pslist |
| 다운로드 | 애플리케이션 제어·웹 다운로드 통제 부재 ① | 페이로드 반입 | pcap |
| 인젝션 | RWX 주입 행위 탐지 룰 부재 ① | migrate 성공 | malfind |
| 지속성 | 사용자 수준 자동실행 모니터링 부재 ① | HKCU 지속성 등록 | printkey |

**작동한 통제 (피해 경감):**
- **사용자 최소권한** → 공격자가 HKLM/예약작업 **시스템 수준 지속성에 실패**, 피해가 사용자 수준으로 억제됨 (근거: HKLM 미발견).
- **사전 메모리 수집 역량** → 파일리스(인젝션) 공격의 전모를 사후 재구성 가능.

**원인 분류:**
- 기술(Technical): 백신/EDR 미작동, RWX 인젝션 행위 탐지 부재, 애플리케이션 제어 부재.
- 프로세스(Process): **엔드포인트 로깅(Sysmon/PowerShell) 미구성** → 메모리 수집에 의존(본 사건 시점).
- 사람(People): 사용자가 출처 불명 실행파일을 직접 실행.

**근거로 확인된 격차 vs 추정:** 인젝션·지속성 탐지 부재는 증거로 확인. "EDR 대응 부재로 인한 미차단"은 실험상 Defender 비활성 전제에 근거(추정 요소 포함).

**핵심 원인 요약:** 본 사고는 **① 출처 불명 실행파일의 실행을 차단할 엔드포인트 통제의 부재와, ② 프로세스 인젝션 등 파일리스 행위를 탐지할 체계의 부재**로 인해 발생하였다. 다만 **최소권한 원칙이 피해 확산을 억제**하였다.

## 9. 대응 및 권고 (8장 격차에 1:1 대응)

**즉시 조치 (격리 · 근절 · 복구)**
1. **격리:** 피해 호스트 네트워크 차단 (C2 통신 차단), 외부 10.0.0[.]10·포트 4444/8000 차단.
2. **근절 — 빠짐없이 (하나라도 놓치면 재부팅 시 부활):** HKCU Run 키 `Updater` 삭제, `C:\Users\Public\svchost.exe` 삭제. 메모리 주입 코드는 파일 삭제로 사라지지 않으므로 **감염 프로세스 정리/재부팅 후 재감염 확인.**
3. **복구:** 확신이 서지 않으면 **OS 재설치 + 신뢰 가능한 백업 복구.**

**재발 방지 (각 항목이 8장 격차에 대응)**
- **EDR/백신 상시 가동 + RWX 프로세스 인젝션 탐지 룰** (← 인젝션 탐지 부재).
- **애플리케이션 제어 / 출처 불명 실행파일 통제 + 사용자 교육** (← 실행 차단 부재, People).
- **Sysmon·PowerShell 엔드포인트 로깅 사전 구성** (← 로깅 미구성) — *실제로 R2에서는 이 로깅을 사전 구성하여 추적 가시성을 확보함.*
- **최소권한 원칙 유지·확대** (← 효과 확인된 통제).

## 10. 결론 및 교훈

**핵심 요약:** 사용자가 웹에서 받은 악성 실행파일을 실행하며 시작된 감염으로, 공격자는 C2 연결 → explorer 프로세스 인젝션 → HKCU 레지스트리 지속성을 수행하였으나 **관리자 권한 확보에는 실패**하였다. 전 과정이 메모리·네트워크·레지스트리에서 교차 확인되었다.

**미해결 질문 (Open Questions):**
- C2 세션이 활성 상태였는데, **메모리 획득 시점 외의 추가 원격 행위**가 있었는가? (시점 스냅샷의 한계)
- `invoice.exe`·`svchost.exe`의 **파일 해시 및 상세 기능** (해시 미산출 — 샘플로 산출 필요)
- **디스크 아티팩트**(Prefetch, $MFT 등)상 추가 흔적 — 디스크 미수집으로 미확인

**교훈 (Lessons Learned):**
- **사전 로깅과 메모리 수집의 중요성** — 인젝션처럼 디스크 흔적이 적은 공격은 메모리 분석 없이는 규명이 어렵다.
- **단일 증거가 아닌 교차검증** — "프로세스가 떠 있다"만으로는 악성을 단정할 수 없으며, 네트워크·주입코드·실행경로를 엮어야 결론에 도달한다.
- **최소권한의 방어 효과** — 권한 억제가 피해 확산(지속성·상승)을 실제로 저지했다. (그리고 이것이 R2에서 공격자가 권한상승을 노리는 출발점이 된다.)

## 【작성 후 개선 필요사항 (Areas Needing Improvement)】

1. **파일 해시 미산출.** `invoice.exe`·`svchost.exe` 샘플의 SHA-256을 산출하여 IOC·위협 인텔 매칭에 활용 필요. (메모리에서 덤프 후 해시 권장)
2. **디스크 포렌식 미수행.** 메모리 단독 수집으로 Prefetch·$MFT·이벤트로그(로그삭제 여부 포함) 등 디스크 아티팩트가 미확인. 메모리+디스크 병행 수집 시 안티포렌식·실행 이력 확증 가능.
3. **인젝션 시각 미확정.** migrate 발생 시각을 직접 기록하는 아티팩트 부재. 가능하면 Sysmon(Event 8 CreateRemoteThread / Event 10 ProcessAccess) 로깅으로 시각·주체 확증 권장. *(R2에서 Sysmon을 사전 구성한 이유.)*
4. **C2 페이로드 내용 미해석.** meterpreter 본체(~1MB)는 암호화/스테이지드라 내용 자체는 미해석. 명령 이력 등은 메모리 내 추가 분석(문자열·세션 아티팩트)로 보완 여지.
5. **활성 세션 범위의 한계.** 시점 스냅샷이라 획득 전후 공격자 행위를 포착 못 함. 실환경이라면 네트워크 지속 캡처·EDR 텔레메트리로 보완 필요.
